# Documentation Guide

This repository keeps only short instructions that are needed while working directly in the code.

## Keep Here

- `frontend-structure.md`: where page HTML, Web Components, stories, and styles live.
- `accessibility-checklist.md`: checks to run before opening a frontend PR.
- `api-expectations.md`: the current contract between the frontend and backend.

## Keep In The Wiki

Use the project wiki for information that explains team-wide decisions or processes:

- why the project uses Carbon Web Components and HTML page entry points
- architecture decisions and alternatives that were considered
- deployment and hosting policy
- Storybook and visual regression policy
- frontend onboarding, branching, review, and team workflow

The wiki is the source of truth for those topics. Avoid adding a second long-form explanation to
this repository when the information is shared across teams or likely to change as the project
evolves.

The links to the relevant wiki pages are collected in the root `README.md` and the frontend
onboarding materials.
